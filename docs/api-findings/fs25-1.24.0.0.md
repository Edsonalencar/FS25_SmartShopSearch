`PLACEABLE` são números. Assinaturas e comportamento detalhado ainda requerem
teste.

## Catálogo base

- `tests/fixtures/catalog/base.xml`: dump real, XML válido, 1.294 itens com
  `xmlFilename` único; todos classificados como `base` no save só com o spike.
- Espécies observadas: `1` (750), `2` (531), `3` (13). O mapeamento exato deve
  ser confirmado antes de alterar filtros de espécie.
- `storeItem.specs` só forneceu valores para 4 itens nesta execução. A
  cobertura muda com os itens visitados na loja; a estrutura e a extração
  secundária precisam de investigação.
- `si.dlcTitle` é string vazia para itens base. Tanto o spike quanto
  `StoreCatalogSource` foram corrigidos para não tratar `""` como DLC.
- O dump exporta specs numéricas presentes em `storeItem.specs`; não contém
  ainda specs lidas dos XMLs de veículo.

## Desempenho inicial

`sssSpikeBench` na primeira sessão: `getItems()` retornou 1.305 itens;
leitura de 100 XMLs em 70,61 ms (0,706 ms/item). Ainda não é benchmark de
busca nem do índice.

## GUI

As capturas enviadas pelo usuário confirmam que `sssSpikeGui` exibiu três
itens na ordem passada a `setDisplayItems`: Rigitrac SKH 60, Landini REX 4 GT
e New Holland TK4.80 Methane Power. A ordem não foi reclassificada pela GUI.
`sssSpikeGuiEmpty` exibiu a mensagem nativa "Não há itens nesta página.".
Ambos os comandos executaram sem erro no log. Isso confirma o protótipo de
categoria virtual ordenada e estado vazio; compra, detalhes e retorno ainda
precisam de smoke no mod principal.

Executar perfis base+dlc e base+mods; confirmar assinaturas de GUI, input,
XML e TestRunner; verificar specs, compatibilidade, ModHub, placeables e
formato do ícone. Este documento registra apenas o que a evidência atual
suporta.
